# UCUG1903 Assignment 3

Song A: 1 1 5 5 | 6 6 5 - | 4 4 3 3 | 2 2 1 -

The completed tasks generate five-harmonic notes, a per-note hit envelope,
two WAV melodies, FFT comparisons, STFT plots and three parameter sweeps.

## Run

Requires base MATLAB (verified with R2026a Update 3). No Signal Processing
Toolbox or files from the other labs are required.

From this folder:

~~~matlab
run_lab3
run_lab3_tests
~~~

From the repository root:

~~~matlab
addpath('lab3')
run_lab3
run_lab3_tests
~~~

The default output is this folder's output/, independent of MATLAB's current
working directory. An explicit output directory can also be selected:

~~~matlab
run_lab3('C:/path/to/another/output')
~~~

The scripts do not automatically play sound or open persistent figures.
To listen:

~~~matlab
[y, fs] = audioread(fullfile('output','task2_timbre_melody.wav'));
sound(y, fs)
~~~

For just one task, add common, task1 and task2 to the path, then call
play_melody_timbre followed by frequency_analysis. Configuration is in
common/lab3_config.m. Both variants use identical notes, timing and gain.

## Outputs

- task2_harmonic_melody.wav: harmonics only.
- task2_timbre_melody.wav: harmonics multiplied by the hit envelope.
- Both WAVs are mono, 8000 Hz, 24-bit PCM, 51200 samples / 6.4 seconds.
- figures/: ten PNGs covering every required comparison.
- notes.csv: inclusive MATLAB sample indices and score timing.
- audio_metrics.csv: peak, RMS, boundary jump and WAV quantization error.
- harmonic_peaks.csv: measured frequency bins for Do, Sol and La.
- stft_experiments.csv: actual window, overlap, FFT and frame parameters.
- test_results.csv: deterministic Lab 3 test results.
- stft_baseline.mat: raw baseline analysis data (regenerated by the demo).
- verification.json: independent ZIP reproduction record, when performed.

The historical task2_ WAV filenames are retained from the provided template;
the synthesis is Task 1 of Assignment 3. Pre-existing course WAVs under
task2/output/ are preserved in the working repository and are not used.

## Analysis conventions

The standalone FFT uses a rectangular segment and single-sided peak-amplitude
normalization. Odd and even lengths treat the last frequency bin correctly.

stft_base directly implements complete-frame segmentation, a symmetric Hamming
window and FFT. It drops incomplete trailing frames and reports their count.
The current experiment lengths produce no discarded samples. Frame centers are
the mean time of their first and last samples. Magnitude is divided by the
window sum and doubled except DC and even-length Nyquist. The displayed scale
is 20*log10(amplitude), from -80 to 0 dB relative to amplitude 1, not PSD.

The window/overlap/FFT sweeps use the enveloped melody. The baseline compares
both versions under identical settings. Zero-padding changes bin spacing,
not the amount of signal data observed.

## Validation

run_lab3_tests executes 12 checks: harmonic amplitudes, alias rejection,
envelope shape and short lengths, score continuity and per-note shaping,
WAV quantization and exact PCM re-encoding, odd/even FFT normalization, STFT
versus an explicit DFT, tone amplitudes, frame times, DC/Nyquist/tail handling,
and zero-padding consistency. One check probes an optional spectrogram
reference; in this environment that function is absent, so the explicit-DFT
reference provides the numerical validation.

The main project regression suite also passed 18/18 tests. These external
project tests are not dependencies of this standalone submission.

## Report and packaging

The submission ZIP contains Lab3_Report.pdf at its top folder. The working
copy of the report is output/pdf/Lab3_Report.pdf. It includes the user's
listening observation that the enveloped version sounds more natural.

Optional report regeneration:

~~~text
python -m pip install reportlab pillow
python build_report.py
python package_lab3.py
~~~

Python is used only to lay out the PDF and package files; synthesis and analysis
are MATLAB. build_report.py also writes a readable Markdown report source.
Generated audio, figures, data and ZIPs are excluded from version control.
The supplied package is for submission to Canvas; no upload is performed by
these scripts.
